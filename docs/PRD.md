# Study Journal 웹앱 PRD

Nov 6, 2026 · @Kim

## 1. 개요 및 문제 정의

Study Journal은 매일의 공부를 '계획 → 진행 → 완료 → 회고' 흐름으로 기록하고, AI가 요약·정리·다음 학습 가이드를 만들어 주는 개인용 학습 저널 웹앱이다.

**해결하려는 문제**

- 공부한 내용이 노트 앱, 클로드 대화, 사진, PDF 등에 흩어져 있어 나중에 다시 찾기 어렵다.
- "오늘 뭘 했는지"는 기록해도 "지금 진행 중인 것"과 "앞으로 할 것"이 한눈에 연결되지 않는다.
- 매일 회고를 쓰는 데 시간이 들어 꾸준히 이어가기 어렵다.
- 날짜별, 과목별로 다시 보기 좋게 정리된 형태가 없다.

**한 줄 정의**: 하루 5분 입력하면 AI가 그날의 학습 저널과 내일의 가이드를 만들어 주는 공부 기록 도구.

## 2. 목표 및 성공 지표

MVP의 목표는 '혼자 매일 쓰는 습관'을 만드는 것이다. 사용자는 우선 본인 1명이며, 이후 공개 여부를 판단한다.

| 목표 | 측정 지표 | 목표값 (출시 후 4주) |
| --- | --- | --- |
| 매일 기록하는 습관 | 주간 기록 일수 | 주 5일 이상 |
| 입력 부담 최소화 | 하루 기록 작성 시간 | 평균 5분 이하 |
| AI 정리의 유용성 | AI 저널 초안을 그대로 또는 약간 수정해 저장한 비율 | 70% 이상 |
| 다시 찾아보기 쉬움 | 과거 기록 검색 후 원하는 내용 찾기 | 30초 이내 |
| 학습 연속성 | 계획(앞으로 할 것) 중 완료 처리된 비율 | 50% 이상 |

**비목표 (MVP 범위 밖)**: 다중 사용자 협업, 소셜 공유, 네이티브 모바일 앱, 결제.

## 3. 타깃 사용자 및 사용 시나리오

1차 사용자는 여러 과목(AI, 수학, 영어, 코딩)을 동시에 독학하며 Claude 같은 AI 도구를 적극 쓰는 성인 학습자다.

**시나리오 A — 아침 (2분)**

1. 앱을 열면 '오늘' 화면에 어제 AI가 제안한 오늘의 할 일 3개가 보인다.
2. 필요하면 수정하고 '오늘 계획 확정'을 누른다.

**시나리오 B — 공부 중 (수시)**

1. 공부하다 생긴 메모, 캡처 이미지, PDF, 클로드 대화 내용을 '빠른 추가'로 던져 넣는다.
2. AI가 자동으로 과목 카테고리와 태그를 붙인다.

**시나리오 C — 저녁 (5분)**

1. '하루 마무리'를 누르면 AI가 오늘 입력한 자료를 요약한 저널 초안을 만든다.
2. 사용자는 느낀 점 한두 줄을 덧붙이고 저장한다.
3. AI가 내일 할 일과 복습할 개념을 제안한다.

**시나리오 D — 주말 회고**

1. 주간 뷰에서 과목별 공부 시간과 완료한 항목을 본다.
2. AI가 주간 리포트(잘한 점, 막힌 부분, 다음 주 방향)를 작성한다.

## 4. 핵심 기능

학습 항목은 네 가지 상태로 움직인다: **앞으로 할 것(Backlog) → 오늘 할 것(Today) → 진행 중(In Progress) → 완료(Done)**. 매일의 기록은 이 항목들과 '데일리 저널'로 묶인다.

| 기능 | 설명 | 단계 |
| --- | --- | --- |
| 데일리 페이지 | 날짜별 1페이지: 오늘 계획, 진행 중, 완료, 학습 노트, 저널 | MVP |
| 학습 항목 보드 | 앞으로 할 것 / 진행 중 / 완료를 칸반으로 관리, 드래그로 상태 변경 | MVP |
| 빠른 추가 | 텍스트, 링크, 이미지, PDF를 한 입력창에 붙여넣기 | MVP |
| 카테고리·태그 | 과목(AI, 수학, 영어 등) 카테고리 + 자유 태그, 색상 지정 | MVP |
| AI 요약 | 오늘 입력한 노트·자료를 핵심 개념 3–5개로 요약 | MVP |
| AI 저널 초안 | 하루 마무리 시 저널 초안 자동 작성, 사용자가 편집 후 저장 | MVP |
| AI 다음 학습 가이드 | 내일 할 일, 복습할 개념, 막힌 부분 해결 방향 제안 | MVP |
| 캘린더 뷰 | 월간 달력에 기록한 날 표시, 날짜 클릭 시 데일리 페이지로 이동 | MVP |
| 검색 | 제목·본문·태그 전체 검색 | MVP |
| 이미지·PDF 스캔 | 필기 사진, 교재 캡처, PDF에서 텍스트 추출 후 요약 | v1.1 |
| 주간·월간 리포트 | 과목별 공부 시간, 완료 항목, AI 회고 리포트 | v1.1 |
| 복습 알림 | 간격 반복(1·3·7일) 기준으로 복습할 노트 띄워주기 | v1.1 |
| AI 퀴즈 | 저장된 노트로 확인 퀴즈 생성 | v1.2 |
| 의미 기반 검색 | "지난달 배운 역전파 관련 내용"처럼 자연어로 찾기 (pgvector) | v1.2 |
| 내보내기 | 마크다운/PDF로 기간별 내보내기 | v1.2 |

## 5. AI 기능 상세

AI는 '대신 써주는 도구'가 아니라 '정리를 돕는 편집자' 역할이다. 모든 AI 출력은 초안으로 제시되고, 사용자가 확인·수정한 뒤에만 저장된다.

| AI 기능 | 입력 | 출력 | 실행 시점 |
| --- | --- | --- | --- |
| 자동 분류 | 새로 추가한 노트·자료 | 과목 카테고리, 태그 2–4개 | 저장 직후 |
| 노트 요약 | 노트 본문, 링크 내용, 클로드 대화 붙여넣기 | 핵심 개념 3–5개 + 한 줄 요약 | 요청 시 / 하루 마무리 |
| 문서·이미지 스캔 | 이미지, PDF | 추출 텍스트 + 요약 (Claude 비전 사용) | 업로드 시 |
| 데일리 저널 초안 | 그날의 완료 항목, 노트, 사용자 한 줄 소감 | 배운 것 / 어려웠던 것 / 내일 할 것 구조의 저널 | 하루 마무리 |
| 다음 학습 가이드 | 최근 7일 기록, Backlog, 진행 중 항목 | 내일 할 일 3개 + 복습 개념 + 막힌 부분 해결 팁 | 하루 마무리 |
| 주간 리포트 | 7일치 저널·항목 | 과목별 진행 요약, 패턴, 다음 주 방향 | 매주 일요일 밤 (자동) |

**구현 원칙**

- 모델: Claude API. 분류·짧은 요약은 Haiku급, 저널·가이드·스캔은 Sonnet급으로 나눠 비용을 줄인다.
- 출력은 JSON 스키마로 받아 화면에 구조화해서 보여준다 (tool use / structured output).
- API 키는 Supabase Edge Function 또는 Next.js 서버 라우트에서만 사용하고, 브라우저에 노출하지 않는다.
- 같은 날 같은 요청은 결과를 캐시해 중복 호출을 막는다.
- 사용자별 하루 AI 호출 한도를 둬서 비용 폭주를 막는다.

## 6. 정보 구조 및 화면 구성

가독성의 핵심은 '오늘'을 기본 화면으로 두고, 날짜·카테고리·상태 세 축으로 같은 데이터를 다르게 보여주는 것이다.

| 화면 | 주요 구성 | 탐색 축 |
| --- | --- | --- |
| 오늘 (홈) | 상단 날짜 + 연속 기록 일수, 오늘 할 것 체크리스트, 진행 중 카드, 빠른 추가 입력창, '하루 마무리' 버튼 | 날짜 |
| 데일리 페이지 | 그날의 계획·완료·노트·AI 요약·저널을 한 페이지에, 이전/다음 날 화살표 | 날짜 |
| 보드 | 앞으로 할 것 / 진행 중 / 완료 칸반, 카테고리 필터 | 상태 |
| 캘린더 | 월간 달력, 기록한 날은 카테고리 색 점으로 표시 | 날짜 |
| 카테고리 | 과목별 누적 노트, 진행률, 최근 학습일 | 카테고리 |
| 노트 상세 | 원문, 첨부, AI 요약, 관련 노트 링크 | — |
| 리포트 | 주간·월간 요약, 과목별 시간 그래프 | 기간 |
| 설정 | 카테고리 관리, AI 사용량, 내보내기 | — |

**디자인 원칙**

- 데스크톱은 좌측 사이드바(오늘 · 보드 · 캘린더 · 카테고리 · 리포트), 모바일은 하단 탭바.
- 과목별 고정 색상을 모든 화면에서 똑같이 사용해 한눈에 구분되게 한다.
- AI가 만든 내용은 연한 배경 + 'AI 초안' 라벨로 사용자가 쓴 내용과 구분한다.
- 다크 모드 지원, 한국어 기본 + 영어 전환.

## 7. 기술 스택 및 아키텍처

Next.js 앱을 Vercel에 배포하고, 데이터·인증·파일·예약 작업은 모두 Supabase에 두는 구성을 권장한다. 이미 쓰고 있는 도구만으로 구성되어 새로 배울 것이 거의 없다.

&#91;embedded content: 시스템 아키텍처 · 브라우저, Vercel, Supabase, Claude API\]

브라우저는 로그인과 일반 데이터를 Supabase에 직접(RLS 보호) 요청하고, AI 기능만 Vercel 서버를 거쳐 Claude API를 호출한다.

| 영역 | 선택 | 이유 |
| --- | --- | --- |
| 프론트엔드 | Next.js (App Router) + TypeScript + Tailwind CSS + shadcn/ui | 이미 Next.js 경험이 있고, UI 컴포넌트를 빠르게 조립할 수 있음 |
| 에디터 | Tiptap (또는 마크다운 에디터) | 노트·저널에 제목, 목록, 코드 블록, 이미지 삽입 |
| 호스팅 | Vercel (기본), Netlify (대안) | Vercel은 Next.js 서버 기능 지원이 가장 매끄럽고 PR마다 프리뷰 배포. Netlify는 랜딩·문서 사이트용으로 활용 |
| DB · 인증 · 파일 | Supabase (Postgres, Auth, Storage, RLS) | 한 곳에서 관리, 무료 티어로 개인 사용 충분 |
| 예약 작업 | Supabase pg\_cron + Edge Functions | 주간 리포트, 복습 알림 자동 생성 |
| AI | Claude API (Anthropic SDK) | 요약·저널·비전(이미지/PDF 스캔)을 한 API로 처리 |
| 모바일 사용 | PWA (홈 화면 추가) | 네이티브 앱 없이 휴대폰에서 빠른 추가 가능 |
| 개발 도구 | Claude Code + Supabase MCP + GitHub | 마이그레이션, 타입 생성, 배포까지 Claude Code에서 진행 |

## 8. 데이터 모델 (Supabase)

핵심은 `daily_logs`(하루 1행)를 중심으로 학습 항목과 노트가 날짜·카테고리로 연결되는 구조다. 모든 테이블에 `user_id`를 두고 RLS 정책 `user_id = auth.uid()`를 적용한다.

| 테이블 | 주요 컬럼 | 용도 |
| --- | --- | --- |
| profiles | id, display\_name, locale, timezone | 사용자 설정 (시간대 기준으로 '오늘' 계산) |
| categories | id, user\_id, name, color, sort\_order | 과목 카테고리와 고정 색상 |
| study\_items | id, user\_id, category\_id, title, status, planned\_date, started\_at, completed\_at | 앞으로 할 것 / 오늘 / 진행 중 / 완료 항목 |
| daily\_logs | id, user\_id, log\_date (사용자별 유니크), plan\_confirmed\_at, reflection, ai\_journal (jsonb), ai\_guide (jsonb), study\_minutes | 날짜별 데일리 페이지 |
| notes | id, user\_id, daily\_log\_id, study\_item\_id, category\_id, title, content (markdown), source\_type, ai\_summary (jsonb) | 학습 노트와 붙여넣은 자료 |
| attachments | id, note\_id, storage\_path, mime\_type, extracted\_text | 이미지·PDF 원본과 스캔 텍스트 |
| tags / note\_tags | id, user\_id, name / note\_id, tag\_id | 자유 태그 (다대다) |
| weekly\_reports | id, user\_id, week\_start, content (jsonb) | AI 주간 리포트 |
| ai\_runs | id, user\_id, kind, model, input\_tokens, output\_tokens, created\_at | AI 사용량 기록과 일일 한도 체크 |

`study_items.status`는 Postgres enum으로 정의한다.

```sql
create type study_status as enum ('backlog', 'today', 'in_progress', 'done');
```

v1.2에서 `notes`에 `embedding vector(1024)` 컬럼을 추가해 의미 기반 검색을 붙인다 (임베딩 모델은 그때 선택).

## 9. 로드맵 및 Claude Code 개발 계획

4주차에 AI 기능까지 포함한 MVP를 완성하고, 그때부터 매일 직접 쓰면서 v1.1을 만든다. 주차는 주 10–15시간 개발 기준 추정이다.

&#91;embedded content: 개발 로드맵 · 5단계, 게이트 1개\]

게이트를 통과하기 전에는 새 기능을 추가하지 않고, 실사용에서 나온 불편을 먼저 고친다.

**Claude Code 진행 방식**

1. 이 PRD를 프로젝트 루트의 `docs/PRD.md`로 저장하고, `CLAUDE.md`에 기술 스택·폴더 구조·코딩 규칙을 적는다.
2. Supabase MCP로 마이그레이션을 적용하고 TypeScript 타입을 자동 생성한다.
3. 기능 하나당 브랜치 하나로 작업하고, Vercel 프리뷰 URL에서 확인한 뒤 머지한다.
4. 각 단계 시작 시 Plan 모드로 구현 계획을 먼저 받고, 확인 후 구현을 진행한다.
5. 단계가 끝날 때마다 Supabase advisors로 RLS·보안 경고를 점검한다.
6. AI 프롬프트는 `lib/prompts/` 폴더에 파일로 분리해 버전 관리한다.

## 10. 리스크 및 열린 질문

| 리스크 | 영향 | 대응 |
| --- | --- | --- |
| AI 비용 증가 | 이미지·PDF 스캔과 긴 저널 생성이 많아지면 월 비용 상승 | 모델 분리(Haiku/Sonnet), 결과 캐시, 일일 호출 한도, `ai_runs`로 사용량 모니터링 |
| AI 요약 오류 | 틀린 개념이 그대로 저장될 수 있음 | 항상 'AI 초안'으로 표시하고 사용자 확인 후 저장, 원문 항상 보존 |
| 기능 과다 | MVP가 늦어지고 매일 쓰는 습관 형성 실패 | 2주차까지 '오늘 화면 + 하루 마무리'만 완성해서 바로 실사용 |
| 시간대 처리 | 한국·미국 이동 시 '오늘' 날짜가 꼬임 | `profiles.timezone` 기준으로 날짜 계산, `log_date`는 date 타입으로 저장 |
| 개인 정보 | 학습 노트에 개인적인 내용이 포함될 수 있음 | RLS 필수, Storage 버킷 비공개, Supabase advisors로 보안 점검 |
